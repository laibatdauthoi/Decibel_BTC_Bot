# Realtime BTC/USD Paper Bot

`npm run bot:paper` runs the unified data collectors and the durable paper-bot runtime in one Node.js process. Stop standalone `npm start`, `npm run collect:microstructure`, or `npm run collect:data` writers before starting it so the database-set lock can be acquired safely.

The default `PAPER_BOT_MODE=OBSERVE_ONLY` records completed-candle evaluations, candidates, feature gates, marks, and reasons without creating paper risk decisions, simulated fills, live risk intents, or live orders. `PAPER_BOT_MODE=PAPER_SIMULATION` enables only the deterministic paper-risk, simulated-order, simulated-fill, and paper-account lifecycle. Both modes hard-code `liveExecutionEnabled: false`; `LIVE` is not an accepted mode.

`PAPER_SIMULATION` selects at most one deterministic, point-in-time-valid candidate per completed candle. An approved decision creates only SQLite-backed simulated order events and a simulated fill. A rejected decision records its stable reason, updates no trade accounting, and produces no fill. Duplicate or restarted candle delivery is suppressed by the shared evaluation identity before risk or execution can repeat.

Startup always passes through `STARTING -> RECOVERING -> WARMING_UP` before becoming `OBSERVING` or `PAPER_ACTIVE`. The health listener is installed before unified-runtime startup and immediately checks the current status. A full uninterrupted `HEALTHY_STABILIZATION_SECONDS` period is required; degradation cancels and resets that period. `PAPER_BOT_READINESS_TIMEOUT_SECONDS` defaults to 900 and halts fail-closed with `PAPER_BOT_READINESS_TIMEOUT` instead of waiting forever.

Each warm-up is stored as a versioned stabilization attempt. The `WARMING_UP` state, start time, deadline, previous state, and transition reason are committed atomically before its single deadline timer is scheduled or logged. Completion records configured and actual duration. Degradation retains the cancelled attempt, recovery creates a new generation, and a restart requires a fresh full period when continuous health cannot be proven.

`bot:paper` is the sole signal owner in composed mode; child collectors register signals only in their standalone commands. On SIGINT or SIGTERM it stops paper ingestion, drains or checkpoints workers, awaits the unified candle and microstructure shutdown, closes repositories, releases locks, and only then persists `STOPPED` and emits `paper_bot_stopped`. `PAPER_BOT_SHUTDOWN_TIMEOUT_MS` bounds the complete sequence. An incomplete shutdown remains non-stopped and returns a nonzero status. A clean stop releases every lock so an immediate restart is supported.

Live WebSocket candles completed during warm-up are durably recorded as `SKIPPED/PAPER_BOT_NOT_READY`, advance the high-water mark, and are never replayed as trades. REST catch-up does not emit live evaluation events. After readiness, every live completed 5-minute candle receives one evaluation row and concise summary, including zero-candidate candles. Duplicate and reconnect events are idempotent.

Every process run owns a durable paper-bot session ledger entry recording its mode, fail-closed live-execution flag, startup recovery result, latest evaluated candle close, shutdown outcome, reason, and final state. Clean shutdown closes the session only after workers and the unified data runtime have stopped. Legacy session rows are preserved by the versioned migration.

Each completed-candle decision has a stable idempotency key and a durable evaluation audit containing its owning session, BTC/USD candle open and close times, 5-minute timeframe, start/completion times, strategy and risk decisions, observe-only reason, risk-intent/order flags, and consistent before/after account-boundary snapshots. Candle close time is unique across sessions. A restart restores the high-water mark and skips completed evaluations. A crash-visible `STARTED` record is never silently replayed: startup marks it fail-closed as `RECOVERED_SAFE`, retains its audit, and completes its queued notification without creating an intent or order.

The same database maintains a fixed-point paper-account ledger and idempotent simulated-execution journal. It records cash, equity, available balance, signed BTC position size, average entry, realized and unrealized PnL, fees, mark price, and session/evaluation ownership. Completed evaluations mark positions using the completed candle close. Simulated fills support long, short, partial close, full close, and reversal accounting with explicit fees and slippage; duplicate execution keys have no financial effect. Account updates and evaluation completion share one SQLite transaction, and restart restores the latest projection exactly.

These are accounting-only paper actions. They do not create Decibel orders, transactions, signatures, wallet access, or live risk intents. `OBSERVE_ONLY` cannot request a simulated fill and only records decisions and mark-to-market state.

Non-observe paper actions pass through `strategy decision -> durable paper risk decision -> simulated order lifecycle -> simulated fill -> account ledger -> completed evaluation` in one transaction. The deterministic policy limits position size, total and per-trade notional, daily loss, drawdown, and minimum cash reserve; it also applies configured fee/slippage basis points, candle cooldown, and explicit reversal/increase/reduce permissions. Size and exposure limits conservatively resize an otherwise valid request. Invalid size, unavailable collateral, stale marks, loss/drawdown stops, cooldown, or disabled position transitions reject it with a stable reason and no fill.

Risk decisions, order-state events, fills, account projections, and evaluations use stable keys. A duplicate evaluation cannot produce another decision or fill. A crash-visible pending risk decision is retained as `RECOVERED_SAFE` and rejected fail-closed. Restart replays no strategy action and restores the latest evaluation, risk, execution, and account state.

For an operational smoke test, stop standalone database writers, set `PAPER_BOT_MODE=OBSERVE_ONLY`, run `npm run bot:paper`, wait for readiness and a completed candle, then stop with Ctrl+C and confirm `paper_bot_stopped` is the last log. Repeat with `PAPER_BOT_MODE=PAPER_SIMULATION`; approved or rejected paper decisions may appear, but every log and session must still report `liveExecutionEnabled: false`. Run `npm run verify:paper-bot` first for the deterministic multi-candle and restart proof.

WebSocket connectivity does not imply candle continuity. Completed-candle notifications are durably queued and evaluated serially outside the SDK listener. Unchanged duplicate deliveries do not enqueue work. A detected 5-minute gap pauses new paper entries, records the triggering decision as `SKIPPED/CANDLE_GAP_DETECTED`, and performs a bounded, single-flight REST repair of only the missing range. Repaired history is never treated as a retroactive signal, and unsupported synthetic candles are never created. If REST cannot find the interval, the bot remains degraded for operator inspection.

Only newly completed UTC-aligned 5-minute candles after the durable high-water mark are eligible. Candidate priority is score, supported-edge status, fixed candidate-type order, then stable identity. Feature windows use point-in-time 15s, 60s, and 300s data and fail closed on missing, stale, incompatible, or future observations.

Every approved paper entry remains a post-only maker attempt at exactly 40x leverage with variable risk-sized margin. The engineering exit policy uses completed-candle ATR(14), a 1x ATR stop, 1.5R take profit, and a 12-bar maximum hold. These values are fixed and unoptimized. Triggers create reduce-only instructions and do not guarantee fills.

USD 10,000 is an uncapped daily minimum filled-volume objective. It cannot select candidates or alter risk, price, quantity, margin, leverage, TTL, stops, or exits. This runtime contains no wallet, private-key access, signing, Decibel transaction construction, real submission, real cancellation, or live execution adapter.
