# Settings Draft And Saved Configuration Fix

- `ROOT_CAUSE`: The idle-session summary and capacity projection read pending form values, while START sent the saved revision. The shared START predicate also treated unsaved changes as a blocker. The volume description lived only inside the Fixed Target branch.
- `DRAFT_SAVED_ACTIVE_STATE_SEPARATION`: Local `pending` plus `volumeMode` own the draft. App-owned `settings` holds schema-validated backend-confirmed values. `activeSession.configSnapshot` remains the session snapshot. No draft is published into either authoritative state.
- `RIGHT_PANEL_DATA_SOURCE`: Active session snapshot when present; otherwise saved settings. Idle capacity projection uses saved values. The revision selector ignores older and replayed reads; transient read failures retain the last confirmed configuration. Reload begins with an authoritative GET.
- `SAVE_AND_START_BEHAVIOR`: Save validates the draft both in the handler and existing backend validation. An immediate in-flight guard prevents duplicate saves; controls are locked during save. Only a successful, valid, newer POST confirmation updates saved state. Failure preserves saved values. Discard restores saved values, including the unlimited-volume sentinel. START sends only the saved revision, independently of draft dirtiness. Existing readiness gates remain; the UI additionally checks saved capital against current margin evidence. Backend admission checks fresh available margin, and the controller rechecks revision after asynchronous admission before session creation. No automatic saving or START retry was added.
