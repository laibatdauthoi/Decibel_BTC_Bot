# Repeated Start Initialization Rejection Investigation

EXACT_INITIALIZATION_BLOCKER= `decibel_runtime_supervisor_v1.assertSessionStartReady()` refreshed authenticated freshness, found `Dependencies.authenticatedState !== READY`, then threw the static dependency mapping `PRODUCTION_AUTHENTICATED_STATE_INITIALIZATION_REQUIRED`. The static mapping applied even when a snapshot had previously published and simply expired. `ensureDecibelRecoveryAuthenticatedStateV1()` also used a generic initialization code after unsuccessful freshness recovery. Neither code identifies a particular missing account field.

Production PID 13248 / build 5a417ad3ac57f6e1 was confirmed through read-only telemetry and process forensics. The recorded requests were 1793297227618 and 1793297343645; their rejections completed at 1793297239600 and 1793297355256. Both had null session IDs. Since `SessionController.start()` validates before creating a session, and its validation first awaits the venue read, these generic rejections identify the later supervisor readiness assertion, rather than a source-stage HTTP rejection. The first request lasted 11982ms; the second lasted 11611ms. Existing logs do not capture the original evidence age at these exact assertion times. The precise cause of the elapsed time cannot be established retrospectively.

FAILED_AUTHENTICATED_STAGE= No individual failed source stage can be assigned to these two requests from the retained evidence. Later production stderr contains ACCOUNT_OVERVIEW HTTP 500s and timeouts, plus ORDER_HISTORY HTTP 500s, but these entries lack timestamps/request correlation. A transport's lastStage is not proof of the failed batch stage. New instrumentation records each source stage's original epoch start/completion timestamps, whitelisted outcome, leverage/fee/rules timestamps, and admission-time authenticated age/read windows. No raw payloads, account addresses, credentials or headers are added to these diagnostics.

Fields are not universally uninitialized. A read-only runtime snapshot sampled at 1793298083983 showed an account window 1793298077012..1793298077702, position 0 BTC, 0 open orders, equity 8.418601 USD, available margin 8.418601 USD, and 32 historical fills. Its history window was 1793297214667..1793297216809. The assembled snapshot's leverage/fee observations were 1793297216947 / 1793297216989. These are original, stale observations, not current trading authorization. At the sample, AuthState was BLOCKED with STALE, and EconomicEvidenceState was READY. This proves prior publication and distinguishes freshness from initialization; it does not certify current leverage/fees or fresh history. New source diagnostics expose current risk-input clocks independently of the assembled snapshot.

READINESS_NONE_VS_START_BLOCKED_EXPLANATION= `lastStartAttempt` is a historical request result, retained until another explicit request. Existing session diagnostics always projected REJECTED as START_BLOCKED, irrespective of the current readiness blocker. They also read the previous execution blocker before updating it from the supervisor in the telemetry refresh. Changes separate lastStartRejection from current blocker, update current readiness before logging, and include readiness in change detection. With no active session and no current readiness blocker, diagnostics now report WAITING_FOR_USER_START while retaining the rejection. Existing Warning UI shows the previous rejection, its original timestamp, and current readiness; after recovery it explicitly requires another Start and fresh venue verification. No automatic Start is introduced.

UPSTREAM_VS_LOCAL_ROOT_CAUSE= Demonstrated local defects: expired evidence mislabeled initialization; historical rejection represented as a current blocker; one-refresh lag in control diagnostics; redundant economic projection on the auth-only admission path. Upstream HTTP 500s and timeouts are independently observed but cannot be causally assigned to these two rejected requests. Event-loop logs show several-second stalls; their exact contribution is not proven. This change does not claim to fix a venue outage or all freshness delays. Genuine stale, partial, timed-out or failed reads still reject.
